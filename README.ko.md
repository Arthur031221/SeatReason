# SeatReason

자리 규칙이 서로 부딪칠 때 그 이유를 알려 줍니다.

SAT 솔버가 필요한 최소 충돌 집합을 찾는 데 걸리는 시간의 중앙값은 18에서 32밀리초, 가장 느린 경우는 0.38초입니다. 같은 사례의 수정 미리 보기는 중앙값 0.26에서 0.49초입니다. 51건을 5번 실행했고, 방법은 [측정](#측정)에 있습니다.

선생님의 요청은 모두 합치면 성립하지 않을 수 있고, 대부분의 자리 배치 도구는 "해 없음"이라고만 답합니다. SeatReason은 서로 부딪치는 요청만 짚어 주고, 하나씩 포기해 볼 수 있게 하며, 배치가 바뀌기 전에 남은 요청 전체를 확인합니다.

![예시 학급에서 충돌이 나타나고, 수정된 배치에서 바뀐 자리가 테두리로 표시된 뒤, 손으로 옮겨 고정 자리를 깨고 되돌리는 장면](assets/demo.gif)

정적 웹 앱입니다. 이름은 브라우저 안에만 있고 업로드되지 않습니다.

## 사용 전과 후

"앞줄이 모자란 경우" 예시입니다. 학생 24명, 책상 2개가 빠진 5 × 6 교실, 요청 10개입니다.

|                | 전                                        | "Noor: 맨 앞줄"을 고른 후                                 |
| -------------- | ----------------------------------------- | --------------------------------------------------------- |
| 결과           | "이 요청 6개는 동시에 만족할 수 없습니다" | "모든 요청을 만족하는 배치가 가능합니다 (켜진 요청 9개)." |
| 화면 표시      | 요청 6개를 번호와 쉬운 말로 표시          | 움직이는 자리가 교실에서 테두리로 표시됨                  |
| 바뀐 자리      | 없음                                      | 4                                                         |
| 배치 교체 여부 | 아니요                                    | "이 배치를 쓰고 그 요청을 끄기"를 눌렀을 때만             |

## 배치가 만들어지는 과정

1. **학급 입력.** 이름이나 CSV 한 열을 붙여 넣습니다. 최대 40명입니다. 이름이 같은 학생은 내부 id로 구분합니다. 행 수와 한 줄의 자리 수를 정하고 책상 없는 자리를 표시합니다. 교실은 최대 48자리입니다.
2. **요청 추가.** 세 종류가 있습니다. 고정 자리, 앞에서 N줄 이내, 그리고 서로 붙어 앉으면 안 되는 두 학생(좌우와 앞뒤)입니다. 어느 것이든 지우지 않고 끌 수 있습니다.
3. **결과 읽기.** 바뀐 뒤 잠시 후 검사가 worker에서 자동으로 실행되며 취소 버튼이 있습니다. 결과는 해 있음, 해 없음, 판단 불가 중 하나입니다. 해가 없으면 최소 요청 집합이 함께 나옵니다. 그중 하나만 꺼도 나머지는 성립합니다. SeatReason은 집합의 모든 요청을 시험한 뒤에만 그렇게 말합니다.
4. **수정 시도.** 충돌하는 요청 중 빼면 나머지가 성립하는 요청마다 "이 배치 미리 보기" 버튼이 있습니다. 미리 보기는 그 요청 없이 새로 배치하되 현재 자리를 가능한 한 유지합니다. 바뀐 자리는 테두리로 표시됩니다. 배치는 그렇게 적힌 버튼을 눌러야만 교체됩니다.
5. **조정과 보관.** 학생을 끌어 놓거나 두 자리를 눌러 맞바꿉니다. 선택한 학생을 버튼 하나로 현재 자리에 고정할 수도 있습니다. 요청을 깨는 이동은 이유와 함께 표시되고 되돌릴 수 있습니다. 학급은 브라우저에 저장되고, `.seatreason.json` 파일로 내보내거나 좌석표와 요청 요약으로 인쇄할 수 있습니다.

## 사용법

페이지는 "앞줄이 모자란 경우" 예시로 열리므로 충돌 목록이 처음부터 보이고, 각 요청 아래에 수정안이 있습니다. 다른 예시는 "예시 학급"에 있습니다.

내 학급으로 쓰려면:

1. 명단을 붙여 넣고 "학급 업데이트"를 누릅니다.
2. 교실 크기를 정하고 책상 없는 자리를 표시합니다.
3. 요청을 추가합니다. 검사는 저절로 다시 시작됩니다.
4. 충돌 중인 요청 아래에서 "이 배치 미리 보기"를 누르고, 마음에 들면 "이 배치를 쓰고 그 요청을 끄기"를 누릅니다.
5. "인쇄"로 좌석표와 요청 요약을 뽑거나 "파일로 저장"으로 백업합니다.

설정, 파일, 제한은 [docs/config.md](docs/config.md)에 있습니다. 단계별 자세한 내용은 [docs/usage.md](docs/usage.md)에 있습니다.

## 측정

`npm run bench`는 고정된 난수 시드로 무작위 학급 두 묶음을 실행한 뒤, 마지막에 고정된 사례 하나를 실행합니다. 두 묶음은 표에 있습니다.

- **무작위 학급.** 6 × 8 교실에 학생 40명짜리 학급 40개를 만들고, 각 학급에 세 종류의 무작위 요청을 12개에서 31개 붙입니다. 이 묶음의 해 없음은 모두 매칭만으로 찾아집니다. 무작위 고정 자리와 앞줄 요청이 먼저 서로 부딪혀서, 떨어뜨릴 쌍은 차례가 오지 않기 때문입니다.
- **떨어뜨릴 쌍.** 80개 학급에서 학생 8명이 앞줄 8자리에 앉아야 하고, 그 사이에 무작위로 14쌍에서 26쌍을 떨어뜨려야 합니다. 고정 자리와 앞줄만으로는 항상 성립하므로, 이 묶음의 충돌은 모두 SAT 솔버에서 나옵니다.

| 묶음        | 결과                     | 건수 | 중앙값          | 가장 느림         |
| ----------- | ------------------------ | ---- | --------------- | ----------------- |
| 무작위 학급 | 해 있음                  | 19   | 8 에서 16 ms    | 17 에서 44 ms     |
| 무작위 학급 | 해 없음, 최소 집합 발견  | 21   | 8 에서 22 ms    | 20 에서 45 ms     |
| 무작위 학급 | 그 사례의 수정 미리 보기 | 21   | 20 에서 43 ms   | 26 에서 71 ms     |
| 떨어뜨릴 쌍 | 해 있음                  | 29   | 3 에서 5 ms     | 10 에서 22 ms     |
| 떨어뜨릴 쌍 | 해 없음, 최소 집합 발견  | 51   | 18 에서 32 ms   | 327 에서 382 ms   |
| 떨어뜨릴 쌍 | 그 사례의 수정 미리 보기 | 51   | 262 에서 492 ms | 1234 에서 2133 ms |

각 칸은 `npm run bench`를 5번 실행한 범위입니다. AMD Ryzen 5 7500F, Node 24.21, 단일 스레드로 브라우저 없이 명령줄에서 실행했습니다. 실행 중 다른 작업도 돌고 있어서 실행마다 값이 다릅니다. 사례 구성은 매번 같습니다. 무작위 학급입니다. 떨어뜨려야 할 쌍이 많은 실제 학급은 더 어려울 수 있습니다. 이 측정은 배치에 20초를 주고 수정 미리 보기에는 제한을 두지 않았습니다. 페이지는 둘이 8초를 함께 씁니다. 여기서 가장 느린 사례는 2.1초였습니다.

측정 끝에 고정 사례가 하나 있습니다. 학생 9명이 모두 앞줄 8자리를 원하는 경우이며, 매칭이 2에서 5밀리초 만에 판정합니다.

테스트는 작은 교실에서 풀이기와 전수 탐색을 비교합니다. 보고된 충돌이 모두 최소인지, 수정된 배치가 모두 독립 검사기를 통과하는지도 확인합니다.

## 제한

- 좁은 교실에서 서로 떨어져야 하는 쌍이 많으면 8초 제한 안에 풀지 못할 수 있습니다. 그러면 화면에 "판단 불가"라고 표시하고 불가능하다고 주장하지 않습니다. 9명이 모두 서로 떨어져야 하는 4 × 4 교실이 그런 예입니다.
- 떨어진다는 것은 상하좌우 이웃이 아니라는 뜻입니다. 대각선 자리는 허용됩니다.
- 수정 미리 보기는 요청을 하나씩 시험합니다. 바뀌는 자리가 가장 적은 수정을 찾지는 않습니다.
- 요청은 세 종류뿐입니다. 성별 균형, 모둠 자리, 순환 배치는 없습니다.

## 설계 원칙

- 검사에 실패하면 실패했다고 말합니다. 시간 초과를 불가능으로 말하지 않습니다.
- 배치는 풀이기의 인코딩과 무관한 코드로 확인합니다. 테스트에서는 모든 충돌을 전수 탐색과 비교합니다.
- 선생님이 직접 배치한 자리는 선생님이 선택할 때만 교체됩니다. 학급이나 요청을 바꾼 뒤에는 요청을 어기는 배치를 다시 짜며, 실행 취소로 되돌릴 수 있습니다.
- 이름은 기기 안에만 있습니다. 예시 학급은 모두 가상입니다.
