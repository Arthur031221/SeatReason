# SeatReason

座位規則互相衝突時，告訴你為什麼。

找出需要 SAT 求解器的最小衝突組合，中位數 18 到 32 毫秒，最慢 0.38 秒。同樣案例的修正預覽中位數為 0.26 到 0.49 秒。51 個案例、跑五次，方法見 [量測](#量測)。

老師的要求加在一起可能無法成立，多數排位工具只回答「無解」。SeatReason 會指出互相衝突的那幾項要求，讓你逐項試著放棄，並在座位表改變之前，先檢查剩下的全部要求。

![範例班級出現衝突，修正後的座位表以外框標出變動座位，接著手動移動破壞固定座位，再復原](assets/demo.gif)

這是一個靜態網頁應用。姓名只留在瀏覽器中，不會上傳。首次造訪後不需要網路也能開啟，瀏覽器也可以把它安裝成應用程式。

## 使用前後

「前排擠不下」範例：24 位學生，5 乘 6 的教室，缺 2 張桌子，共 10 項要求。

|                  | 之前                          | 選擇「Noor 坐在第一排」之後                        |
| ---------------- | ----------------------------- | -------------------------------------------------- |
| 結果             | 「這 6 項要求無法同時成立」   | 「座位表可以滿足所有要求（已開啟 9 項）」          |
| 頁面顯示         | 這 6 項要求，編號並以白話寫出 | 要移動的座位在教室中以外框標示                     |
| 變動座位數       | 無                            | 4                                                  |
| 是否取代原座位表 | 否                            | 只有按下「採用這份座位表，並關閉該項要求」才會取代 |

## 座位表如何產生

1. **描述班級。** 貼上姓名或一欄 CSV，最多 40 位學生。同名的學生以內部 id 區分。設定列數與每列座位數，再標記沒有桌子的位置。教室最多 48 個座位。
2. **加入要求。** 共四種：固定座位、坐在前 N 排、兩位不能相鄰的學生，以及兩位要相鄰的學生（左、右、前、後）。每項都可以關閉而不必刪除。
3. **看結果。** 每次修改之後稍等一下，檢查會自動在 worker 中執行，並有取消按鈕。結果是有解、無解或無法判定。無解時會附上最小的要求組合：關掉其中任何一項，其餘就能成立。只有測試過組合中每一項之後，SeatReason 才會這樣說。
4. **試試修正。** 衝突中，拿掉後其餘要求就能同時成立的每項要求都有「預覽這份座位表」按鈕。預覽會在沒有該項要求的情況下重新排位，並盡量保留現有座位。變動的座位以外框標示。只有按下專門的按鈕，座位表才會被取代。
5. **調整並保存。** 拖曳學生，或點選兩個座位來交換，也可以用一個按鈕把學生固定在目前座位。違反要求的移動會連同原因一起顯示，並且可以復原。班級會存在瀏覽器中，可匯出成 `.seatreason.json` 檔，也可以列印成座位圖加要求摘要。

## 使用方式

頁面一開啟就是「前排擠不下」範例，衝突清單已經在畫面上，每項要求下面都有修正方案。其他範例在「範例班級」中。

使用自己的班級：

1. 貼上名單，按「更新班級」。
2. 設定教室大小，標記沒有桌子的位置。
3. 加入要求。檢查會自動重新開始。
4. 在衝突的某項要求下按「預覽這份座位表」，接受的話再按「採用這份座位表，並關閉該項要求」。
5. 按「列印」取得座位圖與要求摘要，或按「儲存檔案」做備份。

設定、檔案與限制見 [docs/config.md](docs/config.md)。操作步驟的細節見 [docs/usage.md](docs/usage.md)。

## 量測

`npm run bench` 以固定的隨機種子跑兩組隨機班級，最後再跑一個固定案例。兩組在表格裡。

- **隨機班級。** 在 6 乘 8 的教室排 40 個班級，每班 40 位學生，各有 12 到 31 項三種類型的隨機要求。這組的每個無解案例都只靠配對就找得到，因為隨機的固定座位和前排要求會先互相衝突，輪不到要隔開的配對。
- **要隔開的配對。** 80 個班級，8 位學生必須坐進前排 8 個座位，其中有 14 到 26 組隨機要隔開的配對。光看固定座位和前排永遠成立，所以這組的每個衝突都來自 SAT 求解器。

| 組別         | 結果                 | 案例數 | 中位數        | 最慢            |
| ------------ | -------------------- | ------ | ------------- | --------------- |
| 隨機班級     | 有解                 | 19     | 8 到 16 ms    | 17 到 44 ms     |
| 隨機班級     | 無解，並找到最小組合 | 21     | 8 到 22 ms    | 20 到 45 ms     |
| 隨機班級     | 這些案例的修正預覽   | 21     | 20 到 43 ms   | 26 到 71 ms     |
| 要隔開的配對 | 有解                 | 29     | 3 到 5 ms     | 10 到 22 ms     |
| 要隔開的配對 | 無解，並找到最小組合 | 51     | 18 到 32 ms   | 327 到 382 ms   |
| 要隔開的配對 | 這些案例的修正預覽   | 51     | 262 到 492 ms | 1234 到 2133 ms |

每格是 `npm run bench` 跑五次的範圍，在 AMD Ryzen 5 7500F、Node 24.21 上以單一執行緒於命令列執行，不含瀏覽器。跑的時候機器還有其他工作，所以每次結果不同。案例組合每次都一樣。這些是隨機班級。真實班級若有很多要隔開的配對，可能更難。 這個量測給排位 20 秒、修正預覽不設限，而網頁是兩者共用 8 秒。這裡最慢的案例花了 2.1 秒。

量測最後有一個固定案例，九位學生都想坐前排的八個座位。配對在 2 到 5 毫秒內就能判定。

測試會把求解器與小教室上的窮舉搜尋互相比對。測試也會檢查每個回報的衝突都是最小的，以及每份修正後的座位表都通過獨立檢查器。

## 限制

- 在狹小的教室中，大量互相要隔開的配對可能超出 8 秒的時間限制。頁面會顯示「無法判定」，不會宣稱規則不可能成立。9 位學生必須兩兩隔開、教室為 4 乘 4，就是這樣的例子。
- 隔開指的是上下左右的鄰座。斜對角的座位是允許的。「坐在一起」也要求同樣的鄰座，斜對角不算。
- 修正預覽一次只試一項要求，不會搜尋變動座位最少的修正。
- 只有四種要求。沒有性別平衡、分組座位或輪換。

## 設計原則

- 檢查失敗就如實說是檢查失敗。時間用完絕不當成無解。
- 座位表由與求解器編碼無關的程式檢查。在測試中，每個衝突都會與窮舉搜尋比對。
- 老師親手排的座位表，只會因為老師的選擇而被取代。改了班級或要求後，違反要求的座位表會重新排位，「復原」可以拿回原本的。
- 姓名留在裝置上。範例班級都是虛構的。
