# SeatReason

座位规则互相冲突时，告诉你为什么。

找出需要 SAT 求解器的最小冲突组合，中位时间 18 到 32 毫秒，最慢 0.38 秒。同样案例的修正预览中位时间为 0.26 到 0.49 秒。51 个案例、跑五次，方法见 [测量](#测量)。

老师的要求加在一起可能无法成立，多数排座工具只回答「无解」。SeatReason 会指出互相冲突的那几项要求，让你逐项尝试放弃，并在座位表改变之前，先检查剩下的全部要求。

![示例班级出现冲突，修正后的座位表用外框标出变动座位，随后手动移动破坏固定座位，再撤销](assets/demo.gif)

这是一个静态网页应用。姓名只留在浏览器中，不会上传。首次访问后无需网络也能打开，浏览器还可以把它安装为应用。

## 使用前后

「前排挤不下」示例：24 名学生，5 乘 6 的教室，缺 2 张桌子，共 10 项要求。

|                  | 之前                          | 选择「Noor 坐在第一排」之后                        |
| ---------------- | ----------------------------- | -------------------------------------------------- |
| 结果             | 「这 6 项要求无法同时成立」   | 「座位表可以满足所有要求（已开启 9 项）」          |
| 页面显示         | 这 6 项要求，编号并用白话写出 | 要移动的座位在教室中用外框标示                     |
| 变动座位数       | 无                            | 4                                                  |
| 是否替换原座位表 | 否                            | 只有点击「采用这份座位表，并关闭该项要求」才会替换 |

## 座位表如何生成

1. **描述班级。** 粘贴姓名或一列 CSV，最多 40 名学生。同名学生用内部 id 区分。设置行数与每行座位数，再标记没有桌子的位置。教室最多 48 个座位。
2. **添加要求。** 共四种：固定座位、坐在前 N 排、两名不能相邻的学生，以及两名要相邻的学生（左、右、前、后）。每项都可以关闭而不必删除。
3. **查看结果。** 每次修改后稍等片刻，检查会自动在 worker 中运行，并有取消按钮。结果是有解、无解或无法判定。无解时会附上最小的要求组合：关掉其中任何一项，其余就能成立。只有测试过组合中每一项之后，SeatReason 才会这样说。
4. **尝试修正。** 冲突中，去掉后其余要求就能同时成立的每项要求都有「预览这份座位表」按钮。预览会在没有该项要求的情况下重新排座，并尽量保留现有座位。变动的座位用外框标示。只有点击专门的按钮，座位表才会被替换。
5. **调整并保存。** 拖动学生，或点选两个座位来交换，也可以用一个按钮把学生固定在当前座位。违反要求的移动会连同原因一起显示，并且可以撤销。班级保存在浏览器中，可导出为 `.seatreason.json` 文件，也可以打印成座位图加要求摘要。

## 使用方法

页面一打开就是「前排挤不下」示例，冲突列表已经在屏幕上，每项要求下面都有修正方案。其他示例在「示例班级」中。

使用自己的班级：

1. 粘贴名单，点「更新班级」。
2. 设置教室大小，标记没有桌子的位置。
3. 添加要求。检查会自动重新开始。
4. 在冲突的某项要求下点「预览这份座位表」，接受的话再点「采用这份座位表，并关闭该项要求」。
5. 点「打印」获取座位图和要求摘要，或点「保存文件」做备份。

配置、文件和限制见 [docs/config.md](docs/config.md)。操作步骤的细节见 [docs/usage.md](docs/usage.md)。

## 测量

`npm run bench` 用固定的随机种子跑两组随机班级，最后再跑一个固定案例。两组在表格里。

- **随机班级。** 在 6 乘 8 的教室排 40 个班级，每班 40 名学生，各有 12 到 31 项三种类型的随机要求。这组的每个无解案例都只靠匹配就找得到，因为随机的固定座位和前排要求会先互相冲突，轮不到要隔开的配对。
- **要隔开的配对。** 80 个班级，8 名学生必须坐进前排 8 个座位，其中有 14 到 26 组随机要隔开的配对。只看固定座位和前排永远成立，所以这组的每个冲突都来自 SAT 求解器。

| 组别         | 结果                 | 案例数 | 中位数        | 最慢            |
| ------------ | -------------------- | ------ | ------------- | --------------- |
| 随机班级     | 有解                 | 19     | 8 到 16 ms    | 17 到 44 ms     |
| 随机班级     | 无解，并找到最小组合 | 21     | 8 到 22 ms    | 20 到 45 ms     |
| 随机班级     | 这些案例的修正预览   | 21     | 20 到 43 ms   | 26 到 71 ms     |
| 要隔开的配对 | 有解                 | 29     | 3 到 5 ms     | 10 到 22 ms     |
| 要隔开的配对 | 无解，并找到最小组合 | 51     | 18 到 32 ms   | 327 到 382 ms   |
| 要隔开的配对 | 这些案例的修正预览   | 51     | 262 到 492 ms | 1234 到 2133 ms |

每格是 `npm run bench` 跑五次的范围，在 AMD Ryzen 5 7500F、Node 24.21 上以单线程在命令行运行，不含浏览器。运行时机器还有其他任务，所以每次结果不同。案例组合每次都一样。这些是随机班级。真实班级如果有很多要隔开的配对，可能更难。 这个测量给排座 20 秒、修正预览不设限，而网页是两者共用 8 秒。这里最慢的案例用了 2.1 秒。

测量最后有一个固定案例，九名学生都想坐前排的八个座位。匹配在 2 到 5 毫秒内就能判定。

测试会把求解器与小教室上的穷举搜索互相比对。测试还会检查每个报告的冲突都是最小的，以及每份修正后的座位表都通过独立检查器。

## 限制

- 在狭小的教室中，大量互相要隔开的配对可能超出 8 秒的时间限制。页面会显示「无法判定」，不会声称规则不可能成立。9 名学生必须两两隔开、教室为 4 乘 4，就是这样的例子。
- 隔开指的是上下左右的邻座。斜对角的座位是允许的。「坐在一起」也要求同样的邻座，斜对角不算。
- 修正预览一次只试一项要求，不会搜索变动座位最少的修正。
- 只有四种要求。没有性别平衡、分组座位或轮换。

## 设计原则

- 检查失败就如实说是检查失败。时间用完绝不当成无解。
- 座位表由与求解器编码无关的代码检查。在测试中，每个冲突都会与穷举搜索比对。
- 老师亲手排的座位表，只会因为老师的选择而被替换。改了班级或要求后，违反要求的座位表会重新排座，「撤销」可以拿回原来的。
- 姓名留在设备上。示例班级都是虚构的。
